# Журнал решений

Формат: дата — решение — причина.

- 2026-11-06 — Приложение для одного пользователя, под его реальные цели. — Сначала проверить систему на себе.
- 2026-11-06 — Главная проблема: защищать фундаментальные цели от вытеснения новыми. — Результат «пяти почему» вверх и вниз.
- 2026-11-06 — Цикл: инкубатор → WIP → цели/майлстоны → трекер → ретро. — Каждый этап закрывает выявленную причину бросания.
- 2026-11-06 — Три уровня цели: направление, майлстон, действие; майлстон обязателен. — Опыт с английским: без цели практика бросается.
- 2026-11-06 — Пропуск без наказания, консистентность вместо стриков. — Стрики провоцируют бросание после срыва.
- 2026-11-06 — Минимальная версия действия = полкубика. — Плохой день не обнуляет движение.
- 2026-11-06 — Норма не повышается автоматически при отставании. — Давление «догонять» ведёт к бросанию.
- 2026-11-06 — Главный экран: матрица задачи × дни, цвет = категория, интенсивность = глубина. — Баланс с одного взгляда.
- 2026-11-06 — Палитра категорий фиксированная, без красного. — Читаемость и отсутствие ассоциации с ошибкой.
- 2026-11-06 — Слоты постоянны, наполнение меняется; ротация наборов по неделям. — Против монотонности без потери автоматизма.
- 2026-11-06 — Составные задачи (спорт): иконки видов, несколько в день, план/факт, замена = успех. — Баланс и планирование.
- 2026-11-06 — Хостинг: Docker на NAS; клиент — PWA на iPhone; доступ только через приватную сеть. — Доступ отовсюду без открытых портов.
- 2026-11-06 — AI — опциональный слой, не ядро. — Система должна работать без него.
- 2026-11-07 — Разработка: Claude Code интерактивно на NAS в контейнере `claude-dev` (не root, только `/volume3/dev`, без `docker.sock`, токен на один репозиторий); владелец управляет через Remote Control. Без cron и headless. — Владельцу нужен доступ с телефона, а не автоматизация; изоляция защищает данные NAS.
- 2026-11-07 — Деплой: агент пишет код и Dockerfile; compose для запуска принадлежит владельцу и лежит вне репозитория (`/volume3/docker/one-percent/`, только том `./data`, без privileged/host-network/сокета). DSM Task Scheduler раз в 5 минут: новый коммит в `main` → build → `up -d` только при успешной сборке → healthcheck, при провале откат на прежний образ; статус последнего деплоя пишется в файл в `/volume3/dev`. — Compose из репозитория дал бы агенту root на NAS.
- 2026-11-07 — Доступ с iPhone: Cloudflare Tunnel + Cloudflare Access (одноразовый код на почту) на отдельном домене; DNS `sna19.com` не трогаем. Заменяет «только через Tailscale». — Рабочий iPhone без VPN; Funnel открывает приложение публично с одним паролем; поддомены нужны для песочницы. *Заменено 2026-11-08: Funnel + Caddy, см. ниже.*
- 2026-11-07 — Стек v0.1: SvelteKit (adapter-node, TypeScript) + SQLite в одном файле на томе `./data` (better-sqlite3, миграции Drizzle в git); PWA через service worker: оболочка в кэше, офлайн-очередь отметок в IndexedDB. Отметка пишется как upsert по паре (practice, date), чтобы повтор из очереди не задваивал запись. Бэкап — `VACUUM INTO` скриптом, healthcheck — `/health`. — Мгновенный отклик на тап и работа без сети при истёкшей сессии Cloudflare Access; один язык. Выбрал владелец из вариантов A/B/C (канал, «Диалог»).
- 2026-11-07 — Сессия Cloudflare Access длинная (около месяца). — Вход по коду с почты должен быть редким. Поведение cookie Access в PWA с экрана «Домой» ещё не проверено: результат дописать сюда после проверки на iPhone. *Заменено 2026-11-08: Funnel + Caddy, см. ниже.*
- 2026-11-07 — Архитектура NAS: x86_64 (Intel Celeron J4125, ядро 4.4 DSM); базовый образ `node` на Debian (glibc). — Для better-sqlite3 есть готовые сборки linux-x64. Поправка от 2026-11-07: в Docker-сборке `npm ci` всё же компилирует модуль, поэтому в build-стадию добавлены python3, make и g++; в финальный образ они не попадают.
- 2026-11-07 — Seed v0.1: итальянский 5/15 мин, английский вслух 5/10 мин, HBR 1/3 стр, спорт 1/1 трен; категории «Развитие» (синий) и «Здоровье» (зелёный), по цели на практику. — Подтвердил владелец; в спеке дозы для языков не были заданы.
- 2026-11-07 — Два адреса приложения: https через Cloudflare (снаружи, рабочий iPhone) и http://100.75.53.22:3001 через Tailscale, как у openGym (порт 3000 занят им). Встроенная проверка источника форм SvelteKit заменена своей: хост из Origin должен совпадать с хостом запроса, схема не важна. — Встроенная проверка требует один https-адрес и отклоняла настройки по http. Офлайн-открытие работает только по https: service worker браузер запускает только в защищённом контексте. *Адреса заменены 2026-11-08: один https-адрес через Funnel + Caddy, http по Tailscale-IP закрыт. Проверка «тот же хост» для форм остаётся.*
- 2026-11-08 — Внешний доступ ко всем приложениям NAS: Tailscale Funnel + Caddy-замок, отдельное имя на приложение через sidecar-контейнер Tailscale (`tracker.morray-iguana.ts.net`, позже `yael.…`; openGym остаётся на `sna19n.morray-iguana.ts.net`). Приложение публикуется на хосте только на `127.0.0.1`, снаружи доступно лишь через замок. Заменяет решения «Cloudflare Tunnel + Access» и «длинная сессия Access» от 2026-11-07 и адрес по http через Tailscale. — VPN нельзя поставить ни на рабочий iPhone, ни Яэль; отдельный origin на приложение изолирует cookie, хранилище и PWA и даёт каждому человеку свой пароль; схема уже работает у openGym (включая cookie для iOS PWA); без домена, трафик расшифровывается только на NAS. Цена: вход по паролю без защиты от перебора — пароли длинные случайные.
- 2026-11-08 — Строка главного экрана = цель (раскрывается в практики); вторая линза — по формату (сущность Format, у практики необязательна); счёт дня всегда по целям. — Первый день использования: восемь строк и «2/8» демотивируют, а альтернативы (тренажёрка/аэробика) делали полный день недостижимым. Spec 002, выбрал владелец.
- 2026-11-08 — Перед применением миграции схемы приложение само копирует файл базы в `data/backups/pre-migration-<время>.db`. — Данные пользователя — ценность; доступа к боевой базе у агента нет, откат должен быть возможен без него.
- 2026-11-08 — Перегруппировка практик по Spec 002 сделана владельцем вручную в настройках, без миграции данных кодом. — Настройки уже позволяли выбрать цель, имя и формат практики; агент не видит боевую базу, а миграция по именам вслепую рискованна.
- 2026-11-09 — Трекер отвечает на «как я двигаюсь?», а не «что сделать?»: напоминания и уведомления не строим, интегрируем «Напоминания» и Shortcuts (уведомление о времени — в «Напоминаниях», отметка из уведомления — через Shortcut). Расписание задач (допустимые дни) — только для честной оценки и экрана. — Принцип владельца: не дублировать то, что iPhone уже делает хорошо; фокус приложения — заметить затухание движения.
- 2026-11-09 — Недельный план по дням (Spec 003): вкладка «План» первая и по умолчанию; контур = план, заливка = факт; источники — прошлая неделя, с нуля, другая неделя, шаблон с именем; без плана — черновик, а не готовый план; прошедшие дни плана не редактируются. Заменяет «расписание по дням» из v0.2: обычные дни практики (default_days) стали шаблоном для планирования. — Практик стало много, нечастые практики (пианино пн/пт/сб) делали счёт дня нечестным. Выбрал владелец.
- 2026-11-09 — Мягкий лимит практик в плане по умолчанию не задан: предупреждение появляется, только когда владелец задаст лимит в настройках. «Как прошлая неделя» без прошлой недели берёт обычные дни практик. Смена источника возвращает план в черновик до «Утвердить». — Число в спеке не задано; не угадывать продуктовые значения.
- 2026-11-09 — Три вкладки: «Сегодня» (экран по умолчанию, не запоминается), «Неделя» (план и факт, Spec 003), «Всё» (переключатель «По целям / По формату» внутри). На «Сегодня» — карточки: тап ставит норму, повторный тап очищает, долгое нажатие — выбор. — Недельная сетка перегружена для ежедневной отметки; утро всегда начинается с рабочего экрана. Spec 004, выбрал владелец.
- 2026-11-09 — Сделанные карточки с полной глубиной заливаются более тёмным тоном цвета категории (78% и 58% с чёрным) в обеих темах; на половинной глубине текст остаётся тёмным. — Белый текст на светлых тонах тёмной темы был нечитаем; контраст белого теперь не ниже 4,5 для всей палитры.
- 2026-11-13 — Заметка — на практику, а не на день; первая строка видна на карточке «Сегодня». Открывается долгим нажатием, кнопкой «⋯» на карточке (запасной путь: в iOS долгое нажатие иногда перехватывается выделением) и тапом по имени практики в «Неделе» и «Всё». Лист один и для дозы, и для заметки; выбор дозы его не закрывает. — Spec 005, выбрал владелец: карточка говорит «сколько», но не «что именно».
- 2026-11-13 — Редактор заметки — Tiptap 3 (StarterKit без заголовков, кода, цитат и нумерованных списков; Highlight; TaskList/TaskItem). Хранение — JSON документа, сервер проверяет его структуру и размер (до 100 000 символов); заметка никогда не выводится как HTML, поэтому санитизация не нужна. Автосохранение через 0,7 с после ввода и при закрытии; офлайн — своя очередь рядом с отметками; сервер принимает изменение, только если оно позже сохранённого. — Структурированный формат безопаснее HTML и даёт первую строку без разбора разметки.
- 2026-11-13 — Заметка дня живёт в плане (у PlanItem), а не у практики; трапезы — свободный текст с чеклистом, не отдельные объекты. Обнуление галочек — копированием: неделя, шаблон и черновик берут заметки со снятыми галочками, исходная неделя остаётся историей. Кубик по чеклисту: все пункты → норма, половина и больше → минимум, меньше → 0, запись пишется тем же upsert. — Spec 006, выбрал владелец: план питания на каждый день без ручной чистки.
- 2026-11-13 — На карточке «Сегодня» заметка дня рисуется из JSON собственным компонентом (без HTML); у такой карточки отметка — квадратом слева, тап по тексту открывает лист, у практики «по чеклисту» вместо квадрата счётчик «X из Y». В редакторе плана тап по запланированной клетке открывает меню «Заметка дня» / «Убрать из плана», удаление дня с заметкой — с подтверждением. — Редактирование внутри карточки на телефоне дало бы случайные правки при прокрутке.
- 2026-11-13 — «Порядок» на «Сегодня» (#9): отдельный режим с ручками ≡ и перетаскиванием, а не долгое нажатие (оно открывает лист заметки). Порядок один — порядок практик из настроек; список на «Сегодня» встаёт в те же позиции общего порядка, остальные практики не сдвигаются. Сохраняется сразу на сервер (без офлайн-очереди). — Владелец хочет выстроить день по-своему, и этот порядок должен быть тем же везде.
- 2026-11-13 — Карточка «Сегодня» — сетка: шапка (квадрат, название и цель, доза до 36% ширины, «⋯») в одну строку, первая строка заметки и «План дня» — под ней на всю ширину. — Текст заметки переносился посередине экрана.
- 2026-11-14 — Заметку дня можно скопировать на все запланированные дни практики этой недели (сегодня и дальше) кнопкой «На все дни недели» в листе заметки дня; галочки снимаются, прошедшие дни не трогаются, замена существующих заметок — с подтверждением. — Владелец пишет одинаковый план на каждый день недели.
- 2026-11-14 — Навигация (Spec 007 A): нижние вкладки «Сегодня / Неделя / Всё» вместо сегментов сверху; один компонент верхней панели на всех экранах (назад с названием вкладки-источника через ?from=, крупный заголовок со сжатием при прокрутке, до двух иконок, меню «⋯»); иконки — Lucide; ссылки «Изменить план» и «Настройки» внизу экранов убраны. «Новая неделя с нуля» очищает план с сегодняшнего дня после подтверждения. — Единые мобильные конвенции (iOS HIG, Material 3), выбрал владелец.
- 2026-11-14 — Сортировка везде — перетаскиванием за ≡ (Spec 007 B): одно действие sortable для всех списков; стрелки «↑↓» убраны. У категорий, целей и шаблонов недели появился свой порядок (sort_order, миграция задаёт его по id, т. е. как было). Порядок сохраняется на сервере сразу после отпускания. — Единый способ сортировки во всём приложении.
- 2026-11-14 — Новые настройки (Spec 007 C): дерево категория → цель → практика; практика и цель — на своих экранах с автосохранением через JSON-API поверх тех же функций валидации; «+ Практика» / «+ Цель» создают элемент сразу в нужном родителе и открывают его экран; перетаскивание в дереве меняет порядок и родителя, а порядок практик в дереве становится общим порядком (тем же, что на «Сегодня»); справочники «Категории» и «Форматы» и «Архив» — отдельные экраны. Прежний экран — «Старые настройки» (/settings/legacy), без изменений, пока владелец не решит его убрать. — Видно, что в чём лежит; экран практики вмещает все её поля.
- 2026-11-14 — «Шаблон недели» — единое название (Spec 007 D); «план» — всегда конкретная неделя. При утверждении плана — «Новый шаблон» с именем или «Заменить: <имя>» (с подтверждением; id и имя сохраняются, содержимое и заметки дней со снятыми галочками заменяются). Управление шаблонами недели и мягкий лимит практик — на экране плана, меню «⋯» → «Шаблоны недели»: переименование на месте, удаление (в архив, возврат — в настройках), порядок перетаскиванием. — Шаблон нельзя было перезаписать; два имени путали.
- 2026-11-14 — «Сегодня» листается по дням (Spec 007 E): «‹ ›», свайп, кнопка «Сегодня»; заголовок «Вчера / Сегодня / Завтра» или дата; диапазон — текущая и следующая неделя, переход на следующую создаёт черновик плана. Будущий день: заметку дня можно писать, практику — добавить в план дня («Добавить в план этого дня») или убрать (в листе), отметки и галочки недоступны — и сервер не ставит отметку будущему дню даже по галочкам, отмеченным в редакторе. Прошедший день: отметки можно, состав плана нет. — План питания на завтра без редактора недели.
- 2026-11-14 — Отменено правило Spec 004 «тап по карточке ставит норму» (Spec 007 F). Отметка — только чекбоксом слева (зона касания 44 pt); тап по остальной карточке раскрывает её на месте (одна за раз): заметка практики целиком с рабочими галочками, заметка дня, «Минимум / Норма / Количество», ссылки «Изменить заметку» и «Изменить заметку дня». Долгое нажатие на карточке убрано, «⋯» остаётся. В сетках «Неделя» и «Всё» клетки работают как раньше. — Случайный тап при прокрутке переносил практику в «Сделано».
- 2026-11-14 — Ссылки в заметках (#11, дополнение к Spec 005): расширение Link из StarterKit Tiptap; кнопка «Ссылка» седьмой в панели (выделенный текст → спрашивается только адрес, иначе «Название» + «URL»); набранный или вставленный адрес становится ссылкой сам; в редакторе тап по ссылке не переходит по ней, а показывает панель «Открыть / Изменить / Убрать ссылку». На карточке (и в первой строке свёрнутой, и в раскрытой) ссылка открывается в новом окне (`target="_blank" rel="noopener noreferrer"`) и не раскрывает и не отмечает карточку. Разрешены только http, https, mailto; адрес без схемы получает https:// (почта — mailto:); остальное отбрасывается и при сохранении на сервере (ссылка снимается, текст остаётся), и при выводе. Цвет ссылки — отдельный токен для светлой и тёмной темы; на залитой карточке — цвет текста с толстым подчёркиванием. — Владелец держит в заметках ссылки на материалы; HTML по-прежнему не выводится, поэтому проверяется только адрес.
