## Цель v0.1

v0.1 даёт ежедневный экран, на котором видно, где движение по целям затухает, и отметку выполнения в одно касание. Это минимальный ответ на главную проблему: фундаментальная цель не должна молча выпадать из фокуса.

Этап считается полезным, если владелец пользуется им каждый день неделю подряд на четырёх реальных практиках: итальянский, английский вслух, чтение HBR, спорт.

## Шаг 0: стек и каркас

Сначала стек, потом код: предложи 2–3 варианта и дождись подтверждения владельца.

Ограничения для выбора:

- один пользователь, поддержка одним человеком;
- Docker на NAS: агент пишет код и Dockerfile, compose для запуска принадлежит владельцу и лежит вне репозитория;
- данные в одном файле (например SQLite) на томе вне контейнера;
- PWA для iPhone: добавление на экран «Домой», светлая и тёмная тема;
- доступ из домашней сети, а снаружи через Cloudflare Tunnel + Cloudflare Access на отдельном домене, без открытых портов на роутере.

После подтверждения: каркас проекта, healthcheck-страница, скрипт бэкапа файла данных в папку на NAS.

## Модель данных v0.1

В v0.1 четыре сущности из DOMAIN_MODEL.md; остальные поля закладываются позже миграциями.

| Сущность | Поля v0.1 | Заметки |
| --- | --- | --- |
| Category | name, color | цвет из фиксированной палитры 8–10 цветов, без красного |
| Goal | title, category, direction, milestone_text, status | только `active`; майлстон пока текстом |
| Practice | goal, title, unit, min_dose, norm_dose, order | ритм только ежедневный |
| Entry | practice, date, amount | одна запись на практику в день; повторная отметка меняет amount |

Начальные данные (seed): четыре практики владельца — итальянский (минуты), английский вслух (минуты), HBR (страницы, минимум 1, норма 3), спорт (тренировки, минимум 1, норма 1).

## Экраны и поведение

Главный экран — недельная матрица практик × дни; всё остальное вторично.

**Главный экран**

- Неделя с воскресенья по субботу, сегодняшний день выделен.
- Строка на практику, клетка на день; цвет — цвет категории, интенсивность — глубина (см. правила).
- Под названием практики счётчик «N дней без», если N ≥ 2.
- Внизу подсказка «Сегодня в приоритете»: практика с наибольшим N среди не отмеченных сегодня.
- Строка «День»: сколько практик отмечено хотя бы минимально, например 3/4.
- Листание недель назад и вперёд.

**Отметка**

- Тап по клетке сегодняшнего дня ставит норму — одно касание.
- Долгое нажатие открывает выбор: минимум, норма, точное количество, очистить.
- Прошлые дни редактируются так же.

**Настройки**

- Простой список категорий, целей и практик: создать, изменить, архивировать. Без мастеров и онбординга.

## Правила расчёта

Глубина клетки считается от дозы относительно нормы, пропуск никогда не наказывается.

| amount | Глубина | Вид клетки |
| --- | --- | --- |
| нет записи или 0 | 0 | пунктирная рамка, без заливки |
| ≥ min_dose и < norm_dose | 0.5 | светлый оттенок |
| ≥ norm_dose | 1 | полный оттенок |
| > norm_dose | 1+ | самый насыщенный оттенок |

- «N дней без» = дней с последней записи ≥ min_dose; сегодня не считается, пока день не закончился.
- Будущие дни — нейтральные, не пропуски.
- Красного цвета и «сломанных серий» нет нигде.

## Критерии приёмки

v0.1 принят, когда все пункты проверены владельцем на iPhone.

- [ ] Новый коммит в `main` разворачивается на NAS автоматически за 5 минут; при провале сборки или healthcheck работает прежняя версия; статус последнего деплоя виден в файле в `/volume3/dev`.
- [ ] Файл данных лежит в томе `./data` вне контейнера и переживает пересборку.
- [ ] Приложение открывается на iPhone дома и снаружи через Cloudflare Access (вход по коду на почту), добавляется на экран «Домой».
- [ ] Четыре практики из seed видны на главном экране текущей недели.
- [ ] Тап по сегодняшней клетке ставит норму и сразу меняет цвет; долгое нажатие даёт минимум, количество и очистку.
- [ ] Счётчик «N дней без» и подсказка приоритета считаются по правилам.
- [ ] Светлая и тёмная тема читаемы, включая полкубика.
- [ ] Бэкап файла данных запускается и восстанавливается вручную по инструкции в README.

## Среда разработки и доступ

Claude Code работает на NAS интерактивно: владелец говорит с ним с телефона через Remote Control. Фонового запуска по расписанию (cron, headless) нет — решение владельца от 2026-11-06.

| Что | Решение |
| --- | --- |
| Где работает Claude Code | контейнер `claude-dev` на NAS: не root, смонтирована только `/volume3/dev`, без `docker.sock` и без данных NAS |
| Как владелец управляет | Remote Control из приложения Claude на iPhone или claude.ai/code; соединение только исходящее, порты не открываются |
| Живучесть сессии | Claude Code запущен в `tmux`, у контейнера Restart policy: always |
| Доступ к git | fine-grained токен GitHub только на `sna19/one-percent`; личный ключ Mac на NAS не копируется |
| Как Claude Code узнаёт о задачах | владелец пишет «посмотри канал»; Claude Code читает этот документ через коннектор Claude Docs; ссылка на документ записана в `CLAUDE.md` репозитория |
| Доступ к приложению с iPhone | Cloudflare Tunnel + Cloudflare Access (одноразовый код на почту) на отдельном домене, DNS основного домена не трогаем; рабочий iPhone без VPN. Решение владельца от 2026-11-07, см. DECISIONS.md |
| Деплой | DSM Task Scheduler раз в 5 минут: новый коммит в main → build → up -d только при успешной сборке → healthcheck, при провале откат на прежний образ. Compose владельца в /volume3/docker/one-percent/ (только том ./data, без privileged, host-network и сокета); статус последнего деплоя — файл в /volume3/dev |

Последствия для канала учтены: задача про cron удалена из «Очереди», «Протокол» переписан под вызов владельцем.
