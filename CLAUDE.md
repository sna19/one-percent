# Контекст проекта для Claude Code

## Что это
Личное приложение одного пользователя (владельца репозитория) — система целей по философии «1% в день».
Это не продукт для рынка: всё делается под реальные цели и ритм жизни владельца.

## Главная проблема — не терять из виду
**Защищать фундаментальные цели от вытеснения новыми и давать им регулярную свежесть.**
Каждую фичу проверяй вопросом: помогает ли она заметить затухание движения или удержать движение?
Если нет — фича второстепенная. Подробно в docs/CONCEPT.md.

## Рабочий канал
https://claude.ai/artifact/17433pk2Ek3UGUh1LBUofq — документ Claude Docs (вкладки «Протокол», «Очередь», «Диалог», спеки).
Читается через коннектор Claude Docs, когда владелец пишет «посмотри канал». Порядок работы — во вкладке «Протокол».
Задачи берутся только из «Очереди»; копии спек лежат в docs/specs/.

## Документы (читать перед работой)
- docs/CONCEPT.md — концепция
- docs/DOMAIN_MODEL.md — сущности, правила, глоссарий RU→EN
- docs/DECISIONS.md — принятые решения (не пересматривать без явной просьбы)
- docs/BACKLOG.md — текущий этап и порядок работ

## Среда
- Хостинг: Docker (docker compose) на домашнем NAS.
- Клиент: прежде всего iPhone — веб-приложение (PWA), добавленное на экран «Домой»; также браузер на компьютере.
- Доступ: один https-адрес https://tracker.morray-iguana.ts.net — Tailscale Funnel (sidecar) → Caddy-замок (пароль + cookie) → приложение на 127.0.0.1:3001. Порты на роутере не открываются; без замка приложение снаружи недоступно (решение 2026-11-08).
- Один пользователь. Своя авторизация в приложении не нужна: её делает Caddy-замок.
- Compose, порт, sidecar и Caddy — у владельца, вне репозитория. От нас — код и Dockerfile (multi-stage, не root, `/health`, данные в `/data`, `chmod -R a+rX,go-w /app` из-за ACL Synology).

## Соглашения
- Документация и обсуждение — на русском. Код, идентификаторы, коммиты — на английском (см. глоссарий).
- Новое решение → запись в docs/DECISIONS.md (дата, решение, причина).
- Маленькие шаги: одна фича за раз, рабочее состояние после каждого коммита.
- Никаких секретов в репозитории; .env в .gitignore.
- Отметка выполнения — максимум одно касание. Фича, добавляющая трение к ежедневной отметке, требует пересмотра.
- Данные пользователя — ценность: миграции схемы без потери данных, понятный бэкап.
- Мобильный интерфейс в приоритете; светлая и тёмная тема.

## Стек и команды
SvelteKit 3 (adapter-node, TypeScript, Svelte 5) + SQLite (better-sqlite3, миграции Drizzle в `drizzle/`). Обоснование — DECISIONS.md.

```sh
npm run dev           # разработка, данные в ./data
npm run check         # типы (включая service worker)
npm test              # vitest
npm run db:generate   # миграция после правки src/lib/server/schema.ts
```

Деплой: commit и push в `main` → `/work/bin/deploy one-percent` → проверить результат. `/health` показывает время сборки.
Общие правила платформы и деплоя — `/work/CLAUDE.md`.
